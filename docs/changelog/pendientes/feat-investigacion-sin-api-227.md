- **2026-10-25** — issue #227 (Refs), "Investigación sin API de catálogo" — smoke real con Sharel (término "calzado": Selltrix ~24 publicaciones con datos, Zilonix OS ~40, esta plataforma apenas ~6 casi todas "Sin dato" por depender de la API de catálogo de Mercado Libre) confirmó que esa API nunca iba a dar el volumen que necesita Investigación. Un solo PR, sin mergear.

  **A) Se saca la API de catálogo de Demanda/Mercado/Estrategia**: `lib/ml/investigacion.ts` (`buscarInvestigacionProducto`/`calcularResultadoInvestigacion`, con sus ~11 tipos de error de ML) y los dos módulos que dependían de su forma de datos, `lib/ml/investigacionCliente.ts` (#210) e `lib/ml/importacionListadoCliente.ts` (#213/#225), se BORRARON junto con sus tests — confirmado por grep que ningún otro archivo los importaba, y que `/panel/investigacion/seguimiento` (que **no se tocó**, sigue 100% con la API de ML) nunca dependió de ellos. `app/panel/investigacion/page.tsx` quedó reducido a autenticación/permiso + normalizar `termino`/`tab` de la URL — ya no llama a Mercado Libre, ni tiene ningún manejo de error de la API. Las tres pestañas se calculan 100% del lado del cliente en `app/panel/investigacion/PanelInvestigacion.tsx` (nuevo, reemplaza a `PanelDemanda.tsx`, borrado) sobre bloques de listados reales escaneados por la extensión.

  **B) `lib/ml/listadoCliente.ts` (nuevo, puro, 20 pruebas)**: módulo único que reemplaza a los tres anteriores. `clasificarSenalVentas` (portado de `importacionListadoCliente.ts`): Amazon = `"mensual_piso"`, todo lo demás (incluido Mercado Libre) = `"acumulado_sin_periodo"`. `facturacionEstimadaListado` devuelve `null` para cualquier fila que no sea `"mensual_piso"` — nunca se inventa una facturación mensual sobre un acumulado histórico (prueba explícita: un acumulado grande nunca ordena por encima de una tasa mensual real más chica). `ordenarProductos` con los 6 criterios de Selltrix/OS (Facturación est. / Más vendidos / Más calificación / Full / Más económico / Más caro, nulos siempre al final). `calcularResumenBloque` separa `sumaAcumuladaSinPeriodo`/`sumaMensualPiso`, nunca combinadas. `calcularKpisMercado` (vendedores distintos, % Full, % envío gratis, solo Mercado Libre). `generarEstrategiaListado`/`generarVeredictoListado` (portados de `lib/ml/investigacion.ts`, mismos umbrales de ticket) — el veredicto perdió a propósito la clasificación vieja de "demanda alta/baja" (dependía de `date_created`, que un listado nunca expone) y quedó solo con el conteo real de `vendedoresDistintos` (prueba explícita: el veredicto nunca menciona "mes"/"mensual"). `aplicarVendidosConfirmados` (adaptado de #210) sigue completando vendidos reales vía "Completar vendidos" cuando `senalVentas.tipo === "ausente"`, sin importar si el candidato vino de un listado escaneado. `cargarBloques`/`guardarBloques`: persistencia en `localStorage` con `TTL_BLOQUE_MS = 1h`, filtrado al cargar — sobrevive un refresh, un bloque vencido se descarta solo.

  **C) Timeouts unificados a 15s fijos (extensión)**: `extension/background.js` — `TIMEOUT_POR_VARIANTE_MS` (Mercado Libre, ya era 15000, sin cambios), `TIEMPO_MAX_RESENA_MS` (reseñas, 14000 → 15000) y `TIEMPO_MAX_POR_TERMINO_MS` (5 plataformas no-ML, 23000 → 15000) — los tres documentados como un solo valor intencional, no tres números sueltos que coinciden por casualidad.

  **D) Volumen/calidad real**: `extension/lectores/mercadolibre.js` (`leerListado`) reescrito con los selectores reales confirmados contra `zilonix-os-web` (`scraper-listado.js`): `li.ui-search-layout__item`, exclusión de anuncios (`[aria-label="Promocionado"]`), `itemId` solo para links `/MCO\d+/` reales (nunca para `/p/` ni `/up/`, que no son un ítem). Los 5 lectores no-ML (Amazon/Temu/AliExpress/Shein/Alibaba) suman `foto`/`calificación`/`esFull`/`esEnvioGratis` a `leerListado` (antes solo Mercado Libre los tenía) — Alibaba deja `calificación` siempre `null` a propósito: lo que expone ahí es la calificación del proveedor, no del producto, y mezclarlas sería inventar un dato. Vendidos/precio/facturación estimada salen del listado real, nunca de la API de catálogo.

  **E) Fotos ampliables, selector de plataforma, stack y selector de país**: lightbox con un clic real (`page.module.css`, `.fotoClicable`/`.lightbox`) — nunca automático. Selector de plataforma (ML/Amazon/Temu/AliExpress/Shein/Alibaba) reutiliza el botón "Analizar también en: …" de #225, ahora alimentando el stack en vez de una tabla aparte. Stack: la misma búsqueda agrega un bloque nuevo debajo por plataforma con un clic, misma TTL de 1h, nunca mezclado entre bloques. Selector de país de Mercado Libre (`FormularioAnalizar.tsx`): CO (default, único dominio confirmado en vivo) + AR/BR(Mercado Livre)/MX/CL/UY/PE — viaja con la marca de clic (`analizarClic.ts`) hasta `extension/background.js` (`DOMINIOS_ML_PAIS`), que arma la URL contra el dominio real de cada país; los 6 países no-CO usan el patrón público conocido de Mercado Libre, sin confirmar todavía contra staging — documentado así en el código, a corregir si algún país falla. "Seguir en Zilonix" (seguimiento diario) sigue siendo solo Mercado Libre.

  **F) Decisión explícita — sin logos de plataforma (punto 16 del issue)**: se evaluó agregar el logo real de cada sitio y se decidió no hacerlo en este PR — mostrar la marca de un tercero dentro de la interfaz propia de Zilonix es un riesgo real que el pedido mismo anticipaba ("si rompen marca, quitarlos"); se mantiene el badge de texto (`Chip`) ya existente.
