- **2026-11-26** — Refs #422 (fix Reporte de Liberaciones de Mercado Pago): en staging `GET /v1/account/release_report/config` dio 404 y el `POST /config` falló como `mp_sin_config` sin mostrar el status HTTP, bloqueando el saldo disponible. Ahora `asegurarConfigReporteLiberaciones` trata el `POST /config` 409 como `"existente"` y el 400/403 como `{ estado: "omitida", status }` (se loguea con `console.warn` y el reporte se pide igual con las columnas por defecto de Mercado Pago); cualquier otro error lleva su status. `solicitarReporteLiberaciones` trata el HTTP 203 como `mp_reporte_no_creado` (según la doc de MP, el reporte no se creó). Nueva `consultarTareaReporteLiberaciones` (`GET /v1/account/release_report/task/{id}`): si `reporte_pendiente_file` guarda un id de tarea, `sincronizarSaldoMp` pregunta por ella primero — `processed` descarga su `file_name`, `pending`/`processing` sigue en preparación sin pedir otro reporte, `failed`/`deleted` limpia el pendiente y pide uno nuevo. El listado solo considera listos los reportes con `status === "processed"` (o sin status), y `descargarReporteLiberaciones` valida `file_name` (`/^[A-Za-z0-9._-]+$/`, sin `.` ni `..`) antes de armar la URL. `ultimo_error_saldo` guarda el código con el status HTTP (ej. `mp_http:400`, `mp_reporte_no_creado:203`), nunca el body ni tokens; el chip de `/panel/finanzas/disponible` muestra la etiqueta del prefijo más el valor completo. Sin migración; no se tocó `db/schema.ts`.
