  **Bug real encontrado en CI (Postgres, no adivinado)** — la primera versión de la migración 0018 falló en `build-and-test` con `ERROR: unsafe use of new value "aprobar" of enum type accion... HINT: New enum values must be committed before they can be used`. Causa real: `drizzle-orm` mete TODAS las migraciones pendientes de una corrida en **una sola transacción** (confirmado leyendo `node_modules/drizzle-orm/pg-core/dialect.js`) — en una base recién creada (como la de CI, que aplica `0001..0018` de una sola vez) el `ALTER TYPE ... ADD VALUE 'aprobar'/'ejecutar'` de la `0017` todavía no está confirmado cuando la `0018` intenta usar esos valores. Nunca pasa en un deploy real (ahí la `0017` ya está aplicada y confirmada desde antes). Arreglado dentro de la propia migración `0018` (sin tocar `db/migrate.ts` ni ningún otro archivo compartido): un `COMMIT;` suelto como primera sentencia, antes de las 3 que usan esos valores nuevos — confirmado contra el código real de `postgres.js` (`begin()`) que un `COMMIT` sin transacción abierta es un no-op documentado de Postgres (NOTICE, nunca error), así que el `COMMIT` final que agrega `drizzle` al terminar la corrida no rompe nada.
