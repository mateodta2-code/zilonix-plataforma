- **2026-10-29** — issue #273 (bug real reportado por Mateo en staging, ext 0.3.42): "Traer datos de ese link" en `/panel/publicar` mostraba SIEMPRE "Ese link terminó llevando a otro sitio, no a Mercado Libre" (`no_es_mercadolibre`) — con un link normal, uno `/p/`, uno `/up/` y uno `meli.la`. "Importar a Publicar" desde una ficha sí funcionaba (nunca dependió de este mecanismo).

  **Causa raíz**: `extension/background.js` (`alActualizarTab`, dentro de `iniciarImportarLink`) leía `tabActualizada.url` — el 3er argumento de `chrome.tabs.onUpdated` — para decidir si la pestaña de lectura ya llegó a un dominio real de Mercado Libre. **`Tab.url` NUNCA viene sin el permiso `"tabs"` o un `host_permissions` que matchee esa URL** ([docs de Chrome](https://developer.chrome.com/docs/extensions/reference/api/tabs)) — `content_scripts.matches` (lo único que tiene esta extensión, a propósito) no alcanza para esto. Con `permissions: ["storage"]` únicamente, `tabActualizada.url` llegaba SIEMPRE vacío (`""`) — el regex de `esUrlFinalDeMercadoLibre` nunca se llegaba a evaluar contra una URL real, así que SIEMPRE rechazaba, para TODO link, sin importar que `PATRON_DOMINIO_IMPORTAR_LINK_PERMITIDO` sí lo hubiera aceptado. Los tests existentes nunca lo atraparon porque el mock de `dispararTabActualizada` siempre pasaba una URL string de verdad — algo que Chrome real nunca manda sin ese permiso.

  **NO se agregó el permiso `"tabs"` ni ningún `host_permissions`** (serían un permiso nuevo real, visible en la instalación, y una superficie de ataque mayor — se pidió explícitamente no hacerlo). Arreglo real:

  1. **`extension/background.js` (`alActualizarTab`)**: en cada `"complete"`, en vez de leer `tabActualizada.url`, le pide la URL real a la PROPIA pestaña de lectura por mensaje (`chrome.tabs.sendMessage(tabIdLectura, {tipo:"zilonix:sonar-url-importar"})` — funciona sin `"tabs"`, mismo mecanismo que el resto del archivo). Sin respuesta real (`chrome.runtime.lastError`, o ningún content script corriendo ahí todavía — el caso normal de `meli.la` o cualquier salto intermedio, que nunca están en los `matches` del manifest) nunca se corta, se espera el próximo `"complete"`. Con una respuesta real, se valida ese `href` contra `esUrlFinalDeMercadoLibre` (sin cambios en el regex) — si pasa, pide `"zilonix:leer-para-importar"`; si no, corta con `no_es_mercadolibre` y cierra la pestaña. La pestaña se identifica siempre por el `tabIdLectura` que este mismo `background.js` abrió, nunca por nada que la página diga.
  2. **`extension/content.js`**: nuevo tipo de mensaje `"zilonix:sonar-url-importar"` en el `onMessage.addListener` que ya existía — responde `{href: location.href}`, síncrono (ya disponible apenas el content script corre, sin esperar ninguna hidratación).
  3. Se mantiene sin cambios todo lo demás: `esRemitentePublicar`, el cooldown global de 5s, el tope absoluto de 30s, "máxima una lectura a la vez" por pestaña solicitante, el cierre siempre de la pestaña de lectura, el resultado solo a la pestaña solicitante, captcha sin reintento, y que la pestaña de lectura nunca dibuja el panel.

  **Limitación real, documentada (no un bug nuevo)**: sin el permiso `"tabs"`, si `meli.la` terminara redirigiendo a un dominio FUERA de los `matches` del manifest, nunca hay forma real de confirmar a dónde fue (no hay content script ahí para preguntarle) — el tope de 30s sigue cerrando la pestaña igual, pero con `timeout` en vez de `no_es_mercadolibre` (nunca se inventa una razón sin evidencia real).

  **`extension/LEEME.md` corregido**: decía por error que no hacía falta el permiso `"tabs"` para leer `tabActualizada.url` — corregido con la explicación real y el arreglo, en la sección "Importar por link".

  **Tests nuevos/reescritos** (`extension/background.test.ts`): el caso exacto del bug — un link normal, `"complete"` con `tab.url` indefinido en el mock + la pestaña respondiendo su `href` real por mensaje -> pide la lectura, NUNCA `no_es_mercadolibre`; URLs reales con hash/query (`/up/MCOU.../#polycard_client=...`, `/p/MCO...`, `articulo.../MCO-...`); `meli.la` esperando el próximo `"complete"` mientras ningún content script responde, y leyendo recién cuando SÍ responde con un `href` real de Mercado Libre; un `href` final que es un dominio ajeno (`evil.com`) o un spoof (`mercadolibre.com.co.evil.com`, `evilmercadolibre.com`) se rechaza igual; sin ningún content script en ningún salto, el tope de 30s cierra con `timeout`; más las pruebas ya existentes de cooldown/reemplazo de lectura/cierre a mano/captcha, reescritas para pasar por el nuevo mecanismo. El mock `crearChromeMock` suma `setRespuestaSendMessageParaTab` (mezcla por `tabId`, a diferencia de `setRespuestasSendMessage` que reemplaza todo el mapa — necesario para simular 2 pestañas de lectura con respuestas distintas a la vez).
