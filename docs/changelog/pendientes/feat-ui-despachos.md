  Reglas de validación (todas en `lib/ml/despachos.ts` + `lib/filtros-listado.ts`, nunca solo en la página):
  - **Búsqueda** (`?q=`): `ilike()` de Drizzle sobre `shipmentIdExterno` (número de envío) — recortada a 100 caracteres, con `%`, `_` y `\` escapados (backslash primero) para que un comodín de LIKE que venga en el texto nunca cambie lo que se busca.
  - **Estado** (`?estado=`): lista blanca `ESTADOS_DESPACHO_FILTRO` — `pending`/`handling`/`ready_to_ship`, los mismos 3 valores reales de `ESTADOS_IMPRIMIBLES` ya confirmados contra producción en esta misma tarea 2.10 (a diferencia del estado de Pedidos, este SÍ tiene precedente real, no es una lista inventada). Cualquier otro valor se ignora.
  - **Fechas** (`?desde=`/`?hasta=`): solo formato `AAAA-MM-DD` y que sea una fecha real de calendario — "30 de febrero" se ignora en vez de normalizarse solo a marzo. Filtran sobre `actualizado_ts` — **límite real, no inventado**: `despachos_ml` no tiene una fecha propia del despacho (Mercado Libre no la manda en el shipment), así que se usa el único timestamp real que existe en la fila. `hasta` es un límite EXCLUSIVO (antes de las 00:00 del día siguiente en Bogotá), no 23:59:59.999.
  - **Orden** (`?orden=`): `actualizado_desc` (por defecto) / `actualizado_asc`, con desempate por `id` en la misma dirección — sin eso, varias filas con el mismo `actualizado_ts` podrían repartirse distinto entre una página y la siguiente según decida Postgres.
  - **Paginación** (`?pagina=`): entera entre 1 y 10000 (`PAGINA_MAXIMA`), y además nunca mayor que el total real de páginas (si se pide la página 9999 y solo hay 2, se devuelve la 2 — nunca una página vacía).

  `app/panel/despachos/page.tsx`: `searchParams` se tipa como `Record<string, string | string[] | undefined>` (no con campos fijos) y cada parámetro pasa por `normalizarParametro()` antes de usarse como filtro o como `defaultValue` de un campo — Next entrega `string[]` cuando la misma clave viene repetida en la URL (`?q=a&q=b`), y sin normalizar eso tumbaba la página con un error 500.

  `lib/ml/despachos.ts` y `lib/ml/sku.ts`: `contarDespachosPendientes()` y `contarPublicacionesSinSku()`, cada una con `count(*)` y EXACTAMENTE el mismo `WHERE` que su función de listado — nunca una segunda definición de "pendiente"/"sin vincular" que se pueda desalinear con el tiempo. `lib/panel-kpis.ts` ya no trae la lista completa solo para medir su `.length`: sus `contarDespachosPendientes`/`contarSkuSinVincular` quedan como una re-exportación directa de estas nuevas funciones (mismo nombre de siempre, para no tocar a `obtenerKpisPanel` ni al test existente).
