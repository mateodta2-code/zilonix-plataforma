- **2026-11-01** — Refs #319 (ventas nuevas no aparecían solas en `/panel/despachos`): diagnóstico confirmó que el webhook (`app/api/ml/webhooks/route.ts`, PR #346) solo guardaba el aviso (un INSERT, para responder 200 rápido a Mercado Libre) y nunca lo procesaba — eso solo pasaba cuando corría `/api/ml/trabajador`, disparado por el cron de GitHub Actions, que en staging se retrasaba 3-5h (limitación conocida de `schedule` en GitHub Actions, no un bug de configuración). Ahora el webhook intenta procesar `orders_v2`/`shipments` al instante, justo después de guardar el aviso (`intentarProcesarAvisoAhora`, `lib/ml/trabajador.ts`): un solo intento (sin el backoff de 429 del cron), acotado a 5s para no bloquear el 200, y con reclamo atómico de `procesado_ts` (`UPDATE ... WHERE procesado_ts IS NULL`) para que el cron y el webhook nunca procesen el mismo aviso dos veces — si el trabajo real falla, libera el aviso (`procesado_ts` vuelve a null) y lo deja para el cron de respaldo, que sigue sin cambios. Si solo se pasa del tope de tiempo, el webhook responde igual pero **nunca libera el aviso**: el trabajo real sigue corriendo en segundo plano (nunca se cancela de verdad) y es él quien decide — si sale bien no hace falta nada más, si falla recién ahí se libera (fix de la revisión del PR #360: liberar en el timeout mientras el trabajo seguía corriendo producía una carrera con el cron y, si el trabajo huérfano terminaba bien después de liberar, nadie volvía a marcar `procesado_ts` y el cron lo reprocesaba para siempre). Nunca confía en el contenido del aviso: sigue pidiendo la orden/el envío real a Mercado Libre por `lib/ml/cliente.ts`, y solo actúa sobre avisos cuyo `user_id` ya resolvió a una cuenta conectada (eso lo sigue filtrando `recibirAviso`, que ahora también devuelve el id de la fila guardada). Además, `/panel/despachos` (pestañas Pendientes/Despachados) se refresca sola cada 60s mientras la pestaña está visible (`AutoRefrescoDespachos.tsx`, pausado con `document.hidden`) — nunca llama a Mercado Libre, solo relee la base vía el Server Component existente; "Sincronizar ahora" sigue siendo la única acción que dispara un resync completo contra la API.
