- **2026-11-09** — dos fallos reales reportados por Mateo, los dos nuestros:

  **A. Clip en STOREKINGSAS (Mercado Líder Gold) decía "sin reputación"**: Mercado Libre responde 403 `PA_UNAUTHORIZED_RESULT_FROM_POLICIES` cuando subir un Clip falla — documentado oficialmente ([developers.mercadolibre.cl/es_ar/permisos-funcionales](https://developers.mercadolibre.cl/es_ar/permisos-funcionales)) como "la aplicación no tiene el permiso funcional habilitado para este recurso", nunca una señal de reputación del vendedor. Nuestro código (`clipRequiereReputacion`, de la rama FullyLemon del 28/9) interpretó ese código como "cuenta recién conectada sin ventas" sin confirmarlo contra la documentación — nunca miraba si la cuenta era Gold/Platinum.
    - `lib/ml/publicar-reglas.ts`: renombrada a `clipRequierePermisoDeApp` (mismo regex, nombre honesto).
    - `lib/ml/clip.ts`: nueva `ClipPermisoDeAppRequeridoError` (reemplaza `ClipReputacionRequeridaError`) con mensaje real — "Mercado Libre rechazó el permiso de la aplicación... revisar el permiso de Clips en el DevCenter y reconectar la cuenta" — y un campo `detalle` (HTTP + cuerpo crudo de ML, hasta 800 caracteres) separado del mensaje principal.
    - `lib/trabajos/subirClipMultiCuenta.ts` / `app/panel/publicar/clip/tipos-cliente.ts` / `SeccionClip.tsx`: nuevo campo `detalle` en el progreso por cuenta, mostrado en un desplegable "Ver detalle" en la fila de cada cuenta (nunca mezclado con el mensaje corto).
    - **Investigado, sin aplicar cambio** (pedido explícito de Mateo): confirmado contra la documentación oficial de Mercado Libre que `POST /marketplace/items/{id}/clips/upload` es el endpoint correcto para vendedores locales — "Clips can only be uploaded on the seller's local sites" ([global-selling.mercadolibre.com/devsite/working-with-clips](https://global-selling.mercadolibre.com/devsite/working-with-clips)). No hay un endpoint distinto para MCO; no se propone ningún cambio de endpoint.
    - Pendiente fuera de este PR (acción manual de Mateo/Pablo en el DevCenter, no de código): confirmar que la app tenga el permiso funcional de Clips habilitado y reconectar la cuenta STOREKINGSAS.

  **B. Publicidad no aparecía para el Dueño aunque los permisos ya estaban marcados**: en `/panel/roles`, el Dueño muestra la etiqueta "Siempre todo" pero nunca tuvo garantía real — `permisos_rol` solo guarda la FOTO fija que `lib/empresas.ts` copió de `permisosDeDueno()` una sola vez, al crear la empresa. Cuando se agregó un módulo nuevo después (`publicidad`, `promociones`), las empresas con Dueño ya creado se quedaron con menos filas de las que el rol dice tener — sin ningún backfill de datos, el Dueño nunca ve el módulo nuevo.
    - `lib/membresias.ts` (`obtenerMiMembresia`): si el rol es "Dueño", calcula `permisosDeDueno()` en caliente en vez de leer `permisos_rol` — un único punto de cambio, porque `requierePermiso`, el menú (`app/panel/layout.tsx`) y toda página que llama `tienePermiso(permisos, ...)` leen ese mismo `permisos`.
    - Sin backfill de datos ni migración — el fix es 100% de código; `permisos_rol` del Dueño se queda tal cual, simplemente ya no se usa como fuente de verdad para ese rol.
