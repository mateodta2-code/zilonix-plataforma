  **`lib/ml/cliente.ts` — 3 errores tipados nuevos, una sola fuente de verdad (`pedir()`):** `MlNoAutorizadoError` (401 — la conexión ya no es válida), `MlSinPermisoAppError` (403 — la app no tiene permiso para ese endpoint puntual; guarda el endpoint SIN query, nunca el término de búsqueda) y `MlNoDisponibleError` (5xx o tiempo agotado). 429 sigue como `LimiteMercadoLibreError`; 404 sigue siendo "vacío" (respuesta legítima, no un error). Cada caso se loguea con `console.warn(endpoint, estado)` — nunca el token ni el término completo.

  **Quién propaga y quién tolera:** `buscarProductosCatalogo` (la búsqueda principal) propaga los 3 tal cual — es la primera llamada real, no hay nada que "tolerar" ahí. Las auxiliares de enriquecimiento (`obtenerProducto`, `obtenerVendedor`, `obtenerItemMl` nuevo) toleran 403/5xx (devuelven `null`) pero propagan 401 (token inválido de verdad, no tiene sentido seguir). `obtenerOfertasProducto` a propósito NO tolera nada — propaga 401 y 403 tal cual, para que `investigacion.ts` pueda distinguir "sin ofertas reales" de "Mercado Libre no deja ver las ofertas" y contar cada caso aparte.

  **`resolverCategoria`: 3 intentos con 800ms·intento ante 403/5xx** (mismo criterio ya confirmado en producción en `zilonix-os-web/lib/mercadolibre-publicar.js`) — un 403/5xx puntual en este endpoint no tira abajo todo el enriquecimiento por categoría. 401 nunca se reintenta.

  **Bug real de highlights (type ITEM/PRODUCT/USER_PRODUCT):** `obtenerMejoresProductosCategoria` devolvía solo `id[]`, perdiendo el `type` — un id de tipo ITEM (una publicación) se mandaba a `obtenerProducto()`/`GET /products/{id}` (espera un id de catálogo), fallando siempre. Ahora devuelve `{id, tipo}[]`; `investigacion.ts` enruta: PRODUCT → `obtenerProducto`, ITEM → `obtenerItemMl` (nuevo, `GET /items/{id}`), USER_PRODUCT → se ignora y se cuenta (nunca se inventa un mapeo). El filtro de formato de id en la LISTA se relaja a prefijo "MCO" (antes exigía `/^MCO\d+$/`, que descartaba USER_PRODUCT en silencio antes de que nadie lo pudiera contar) — el filtro estricto real sigue en `obtenerProducto`/`obtenerItemMl`, justo donde cada id se usa de verdad en una URL.
