- **2026-10-24** — issue #192 (Refs), bug real: un link de tienda oficial real (`www.mercadolibre.com.co/tienda/colchones-relax?item_id=MCO1657640131&category_id=MCO1574&official_store_id=53573&...`) no se leía y no avisaba nada — ni en la extensión ni en el panel.

  **Extensión (`extension/lectores/mercadolibre.js`, 0.3.1 → 0.3.2)**: `tipoDePagina` no reconocía el path `/tienda/` (solo `/perfil/`, el subdominio `tienda.mercadolibre.*` y `?CustId=`) — para esta URL real, ninguno matcheaba y el panel ni se dibujaba, silencio total. Se suma `/tienda/` como cuarto patrón. De paso, se encontró y corrigió un bug relacionado: el check de `/listado` corría ANTES del de tienda, así que un link real de `_CustId_`/`?CustId=` bajo el dominio `listado.mercadolibre.com.co` (la forma "confirmada en producción" que ya documenta `lib/seguimiento/link.ts`) se clasificaba mal como "listado" — se reordenó, tienda primero. `leerSellerIdDeTienda` sigue sin leer `official_store_id` de la URL a propósito (es el id de la TIENDA OFICIAL, un concepto distinto de `seller_id`, pueden no coincidir — nunca se adivina sin una forma segura de confirmarlo) — sin CustId ni `seller_id` real en el HTML, sigue dando `null`, y el panel de la extensión (`extension/content.js`, `renderizarTienda`) ya mostraba "No se pudo confirmar el vendedor de esta página" en ese caso — eso ya estaba bien, solo hacía falta que `tipoDePagina` llegara a dibujar el panel.

  **Panel (`lib/seguimiento/link.ts` + `lib/seguimiento/seguimientos.ts`)**: bug real encontrado al revisar — `interpretarEnlaceProducto` reconocía cualquier `MCO\d+` en el texto, incluido el `item_id=MCO1657640131` del query de ESTE link de tienda; con tipo "Producto" seleccionado, el seguimiento se agregaba para esa publicación en vez de la tienda, sin ningún error. Nueva `esLinkDeTienda(texto)` — mismos patrones que `tipoDePagina` de la extensión (`/tienda/`, `tienda.mercadolibre`, `_CustId_`, `?CustId=`) — usada para que `interpretarEnlaceProducto` nunca extraiga un id de un link que es claramente de tienda. `interpretarEnlaceTienda` ahora también acepta `?CustId=<dígitos>` como parámetro de query (antes solo `_CustId_<dígitos>` en el path) — misma forma que ya reconoce la extensión (issue #188). Nueva `esLinkTiendaOficialSinIdDeVendedor(texto)` — distingue el caso puntual "`/tienda/` + `official_store_id=` pero sin seller/CustId" para un mensaje de error específico en `agregarSeguimiento`, en vez de caer en el genérico: "Este link de tienda oficial no trae el id del vendedor; abrí la tienda en ML y usá Seguir en Zilonix, o pegá el seller_id / un link con CustId." Con tipo "Producto" y un link claramente de tienda: "Ese link es de una tienda, no de un producto — elegí 'Tienda' como tipo, o pegá el link de la publicación/catálogo."

  **Pruebas nuevas**: `extension/lectores/mercadolibre.test.ts` — `tipoDePagina` reconoce `/tienda/` (con el link real del bug) y sigue reconociendo `/perfil/`/`tienda.mercadolibre`/`?CustId=`, un producto real sigue dando "producto"; `leerSellerIdDeTienda` con el link real del bug (official_store_id, sin seller_id en el HTML) da `null`. `lib/seguimiento/link.test.ts` — `interpretarEnlaceProducto` nunca extrae el `item_id` de un link de tienda; `interpretarEnlaceTienda` acepta `?CustId=` en query y sigue dando `null` para el link real del bug; `esLinkDeTienda`/`esLinkTiendaOficialSinIdDeVendedor` cubiertos con el link real y casos negativos (un producto real, un link con CustId sí resuelto, texto irreconocible).

  **No se tocó**: ninguna migración, permiso, ni otra pantalla — `esLinkDeTienda`/`esLinkTiendaOficialSinIdDeVendedor` nunca se usan para extraer ningún id, solo para decidir el mensaje de error o rechazar un falso positivo.
