- **2026-10-25** — issue #233 (Refs), tercera vuelta de hotfix de smoke de Investigación. El fix de manifest de #231 arregló que el content script se inyectara en los 6 dominios de Mercado Libre, pero el panel seguía sin bloques: "escaneo → 0 productos" para Argentina/Brasil. Causa raíz real, confirmada leyendo el código: `extension/lectores/mercadolibre.js` tenía el site-id de Colombia (`MCO`) hardcodeado en 4 lugares distintos, nunca generalizado cuando #227 agregó el selector de país.

  **A) `clasificarLinkListadoMl` (el bug principal — usada por `leerListado`)**: sus 3 patrones (`/p/MCO…`, `/up/MCOU…`, `MCO-?dígitos`) solo reconocían `MCO`. Un link real de Argentina (`MLA`) o Brasil (`MLB`) nunca matcheaba ninguno de los 3 → `idInfo` daba `null` → `leerListado` descarta la tarjeta ENTERA (`if (!idInfo) return;`) — todas las tarjetas de un listado de cualquier país que no fuera Colombia se perdían, sin importar que el resto de la lectura funcionara bien. También `tipoDePagina` (el check de "producto") y `PATRON_ID_ITEM`/`extraerIdDeUrl` (afectan "Completar vendidos", reseñas y "Seguir en Zilonix" en páginas de producto de otros países) tenían el mismo problema. Corregido con una sola constante compartida (`PREFIJO_ITEM_ML = "MCO|MLA|MLB|MLM|MLC|MLU|MPE"`, site-ids reales y públicos de Mercado Libre) usada en los 4 lugares.

  **B) `tipoDePagina`, el check de "listado"**: solo reconocía el substring `"mercadolibre"` — Brasil usa el dominio real `mercadolivre` (marca en portugués, el mismo dominio que `urlListadoMl` en `background.js` ya arma desde #227). Una URL real de listado de Brasil devolvía `null` (ni "listado" ni nada), así que `leerListado` nunca se llegaba a llamar — 0 productos garantizado, independiente del bug A. Corregido (también en el check de "tienda", mismo patrón).

  **C) `content.js` — `manejarEscaneoAutomatico` todavía podía "rendirse" con 0 productos**: si `esperarListadoEstable` (de #231) agotaba su tiempo sin ver ningún candidato, igual se mandaba ese resultado vacío y se marcaba `yaEnviadoEscaneoAutomatico = true`, cerrando la puerta a cualquier intento posterior aunque el `MutationObserver` siguiera viendo la página cambiar. Corregido: con 0 productos, ya no se manda nada ni se marca nada — se deja que el timeout externo fijo de 15s de `background.js` (sin tocar) decida de verdad, o que un reescaneo posterior lo reintente con más contexto. `maxEsperaMs` de la espera interna sube de 10s a ~14s.

  **D) Contingencia, no una corrección puntual**: si Colombia sigue en 0 después de este PR, el pedido es inspeccionar el HTML real a mano, nunca adivinar. Esta sesión reintentó el acceso directo (`curl`/`WebFetch` contra `listado.mercadolibre.com.co`) y sigue bloqueado por la verificación de cuenta de Mercado Libre desde este sandbox (mismo bloqueo que en #229/#231) — no se inventó ningún selector nuevo para "tapar" esto a ciegas.

  **Prohibiciones reafirmadas (nunca violadas por este PR)**: nunca login/evasión de captcha; nunca Apify; `senalVentas` sin tocar; sin logos de plataforma; ayuda "?" fuera de este PR; `/panel/investigacion/seguimiento` no se tocó; no se mergeó nada.

  **Pruebas nuevas**: `clasificarLinkListadoMl` se sumó al `module.exports` de `mercadolibre.js` (es pura — string de entrada, objeto de salida, sin DOM — nunca necesitó estar afuera salvo que nadie la había probado todavía) con su propia batería de casos en `extension/lectores/mercadolibre.test.ts` (regresión Colombia + los 3 formatos con site-ids de otros países + casos sin match). `extraerIdDeUrl`/`construirLinkSeguirProducto`/`tipoDePagina` suman casos nuevos para Argentina/Brasil (incluido el dominio `mercadolivre.com.br`). 9 pruebas nuevas en total.
