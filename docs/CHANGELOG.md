El `try/catch` que ya existía para este caso (tratarlo como "ya era miembro", no un error) no alcanzaba: en Postgres, una sentencia que falla deja TODA la transacción envenenada hasta un `ROLLBACK` o `ROLLBACK TO SAVEPOINT` — un `catch` de JavaScript no deshace eso solo, así que el `UPDATE` que venía después (marcar la invitación como aceptada) también fallaba, con el mismo error de la primera sentencia. Se envuelve el `insert` riesgoso en `tx.transaction(...)` anidado, que en Drizzle (`postgres-js/session.js`) crea un `SAVEPOINT` real — si choca, solo se deshace esa parte, la transacción de afuera sigue sana para el `UPDATE`.
